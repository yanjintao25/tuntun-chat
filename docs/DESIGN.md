# 飞书大模型聊天机器人 - 架构与开发指南

## 一、整体架构

```
                    ┌─────────────────────────────────────────┐
                    │           飞书开放平台                     │
                    │  (事件推送 / 消息发送 / 日历/待办 API)     │
                    └─────────────────┬───────────────────────┘
                                      │ HTTPS
                                      ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                        你的云服务器 (Node.js)                             │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐  ┌─────────────┐  │
│  │ 飞书 Webhook  │  │  LLM 服务   │  │  功能模块    │  │  后台配置   │  │
│  │ 事件接收/验签 │─▶│ (OpenAI等)  │  │ 日程/代办/   │  │  API + DB   │  │
│  │ 消息解密     │  │  对话与理解  │  │ 每日总结等   │  │  开关与参数  │  │
│  └──────────────┘  └──────────────┘  └──────────────┘  └─────────────┘  │
└─────────────────────────────────────────────────────────────────────────┘
```

- **飞书**：通过「事件订阅」把用户发给机器人的消息推到你的服务器；你的服务再调飞书 API 发消息、读日历/待办等。
- **云服务器**：跑 Node 服务，提供 Webhook 接收、大模型调用、可配置功能逻辑和后台配置 API。

## 二、飞书侧必做配置

### 2.1 创建企业自建应用

1. 打开 [飞书开放平台](https://open.feishu.cn/app) → 创建企业自建应用。
2. 记录 **App ID**、**App Secret**。

### 2.2 机器人能力与权限

- **机器人**：在应用里开启「机器人」能力。
- **权限**（在「权限管理」中申请并发布）：
  - 消息与群组：`im:message`（**收发消息**，待办主动提醒必需）、`im:message.group_at_msg`（接收群 @ 消息）、`im:message.p2p_msg`（单聊）。
  - 若要做日程：日历 `calendar:calendar` 等（按需申请）。待办提醒已用自建表，**不依赖**飞书 Task API。

### 2.3 事件订阅（Webhook）

1. 在应用后台「事件订阅」里选择 **Webhook**。
2. **请求网址**：填你云服务器的公网 URL，例如：`https://你的域名/feishu/event`。
3. **验证**：飞书会发带 `challenge` 的请求，你的服务必须在 1 秒内原样返回 `challenge`（见下方代码）。
4. **订阅事件**：至少勾选「接收消息 v2.0」`im.message.receive_v1`。
5. 若开启「Encrypt Key」，需在代码里做解密（本仓库已预留解密逻辑）。

### 2.4 安全配置（推荐）

- **Verification Token**：在事件订阅里配置，用于校验请求来自飞书。
- **Encrypt Key**：可选，用于加密事件 body，需在服务端解密后再解析。

## 四、核心流程

1. **用户发消息** → 飞书推事件到 `POST /feishu/event`。
2. **验签与解密** → 校验 token、解密（若开启），得到 `im.message.receive_v1`。
3. **先回 200** → 3 秒内必须返回 200，再异步处理逻辑，避免飞书重试。
4. **解析消息** → 取 sender、chat_id、content（文本/富文本）。
5. **功能配置** → 从 DB 读当前开启的功能与参数（如「每日总结」开关、提醒时间）。
6. **LLM 理解** → 把用户原文 + 当前开启的功能列表发给大模型，做意图识别或直接生成回复。
7. **执行能力** → 根据意图调用各模块。待办已实现：LLM 抽 JSON → 写 `todos` 表；日程/每日总结仍为占位。
8. **回消息** → `replyMessage` 回复；待办到期由 `scheduler` 调 `sendTextToChat` **主动推送**。

## 五、可配置功能设计（后台配置）

以下功能可在后台通过 API 或后续的管理界面配置开关和参数。

| 功能       | 状态   | 说明           | 可配置项 |
|------------|--------|----------------|----------|
| 待办提醒   | ✅ 已实现 | 聊天创建/查/完成/取消；SQLite + 定时推送 | 开关、`reminderMinutes` |
| 日程管理   | 🚧 占位 | 查/创日历事件  | 开关、默认日历 ID |
| 每日总结   | 🚧 占位 | 按时间汇总并生成总结 | 开关、总结时间、范围 |

配置存储建议：表结构包含 `key`（如 `schedule.enabled`）、`value`（JSON）、`updated_at`，便于后续加更多功能。

## 六、部署要点（云服务器）

1. **域名与 HTTPS**：飞书要求请求网址为公网 HTTPS（或 http，但不推荐）。可用 Nginx/Caddy 反代到本机 `http://127.0.0.1:端口`。
2. **端口**：本服务监听 3000（可改），防火墙放行；反向代理对外 443。
3. **进程常驻**：用 pm2 或 systemd 跑 `node dist/index.js`（先 `npm run build`）。
4. **环境变量**：在服务器上配置 `.env`（见 `.env.example`），不要提交密钥到仓库。
